# Phase 3 — Révision pour les joueurs : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** révision sur téléphone par lien, scores, présentation grand format.
**Architecture:** questions générées et corrigées par du code pur (`src/modele/revision.ts`), lien encodé/décodé par `src/modele/lien.ts` (CompressionStream, testé sous Node), écrans `src/ui/Revision.tsx` et `src/ui/GrandFormat.tsx`, collections `paquets` et `resultats`.
**Spec:** `docs/superpowers/specs/2026-10-19-triple-threat-design.md` (section Phase 3)

## Review Focus
1. Lien abîmé, tronqué par une messagerie ou d'une autre appli → message clair, rien d'importé (`lien.test.ts`).
2. Document sans action pour le poste choisi → questions « Ne bouge pas », jamais une révision vide sans explication (`revision.test.ts`).
3. Système défensif (actions surtout des X) → les postes proposés sont ceux des défenseurs (`revision.test.ts`).
4. Téléphone en vertical → révision utilisable, rien de coupé (e2e iPhone).
5. Même lien ouvert deux fois → un seul paquet (remplacé), scores conservés.

### 3a — Tâche 1 : `questionsPour(doc, poste) → Question[]`, `verifier(q, reponse) → boolean`, `campActif(doc)`, `postes(doc)`, tests
### 3a — Tâche 2 : collection `resultats`, écran Révision (choix du poste, questions, correction animée, score), onglet Révision et « à retravailler », e2e
### 3b — Tâche 3 : `GrandFormat` (entrées : carte, éditeur), e2e
### 3c — Tâche 4 : `encoderPaquet` / `decoderPaquet` + tests, collection `paquets`, ouverture par lien, mode joueur, mise en page téléphone, e2e iPhone
Chaque tâche : tests d'abord, vitest, tsc, e2e Chromium + WebKit, commit, `npm run deployer`.
